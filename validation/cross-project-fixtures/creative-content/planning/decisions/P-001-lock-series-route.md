## Recommendation

Use one recurring example to move from a familiar browser-chat response to a bounded agent workflow. This favors clarity and continuity over covering many agent use cases.

## Confirmed decision

The series title is **Chat to Action**. Its five episodes form one progression:

1. **A reply is not a workflow.** In ordinary browser-chat use, the person drives each prompt and copy/paste step; an agent can be set up to manage steps toward a result. The interface alone does not decide which one it is. Hook: “The difference is not smarter words. It is what happens after the words.”
2. **An agent works a loop.** In plain language: give it a goal, approved tools, and boundaries; it plans, acts, checks the result, and adjusts or stops. Do not imply perfect autonomy.
3. **Choose agent-shaped work.** Favor recurring, multi-step work that crosses information sources or needs judgment. Keep one-off questions and simple deterministic steps in chat or ordinary automation.
4. **Watch one safe example.** Each week, the agent reads fabricated new enquiries, groups them by urgency, drafts tailored follow-ups, and places them in a review queue. The contrast is manual copy/paste and prompting versus advancing the whole bounded workflow.
5. **Review is part of the design.** The owner checks the source details, recipient, tone, and proposed reply before anything is sent. The closing prompt asks viewers to write one repetitive workflow as “start → steps → review checkpoint.”

Every episode is a friendly, non-technical vertical talking-head video with one simple on-screen example and a runtime below 60 seconds. The scripts avoid hype, fear, vendor-specific feature promises, claims that every workflow needs an agent, and claims that an agent should act without oversight. Screen demonstrations use fabricated business and customer data; nothing is sent or connected to a live system.
